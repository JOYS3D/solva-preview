04Straight answers

Four times out of ten,
we tell people not to.

Custom software is expensive to build and it becomes yours to live with. Here is when it is the wrong call — and what to do instead.

Existing software already does it

ServiceM8, Jobber, Tradify, Cliniko, Xero. If eighty per cent of what you need is already in a product costing fifty dollars a month, building it yourself is a bad trade.

Then: use it, and we connect the missing twenty per cent.

Your process changes every month

Software freezes a way of working. If yours is still moving — a new service, a new pricing model, a partner joining — you would be paying to set concrete on wet ground.

Then: wait until the shape stops moving. Usually a season.

One person is the only user

If it is just you, and the spreadsheet works, the spreadsheet works. A tool earns its cost when several people need the same truth at the same time.

Then: a better spreadsheet and one automation, for a fraction.

The real problem is a habit

Quotes going out late is sometimes a software problem. More often it is a Thursday afternoon problem. No tool fixes a decision nobody is making.

Then: change the routine first. Build only if it survives.
Why say this at all? Because you will find out anyway, six weeks and several thousand dollars in. We would rather lose the project than build something you resent.
05How it gets built

Smallest useful thing.
Used on a real job.

Not a six-month specification. Something you can put in front of a paying customer within weeks, then sharpen with what you learn.

01

Watch the work

Take one job that finished last week and walk it through end to end. Where did the time actually go?

02

Find the awkward part

There is always one step that costs an hour and produces nothing. That is what gets built.

03

Agree scope and price

Both fixed before a line is written. No open-ended hourly work, no surprises at the end.

04

Build the narrow version

One workflow, done properly, rather than six done roughly. It has to survive contact with a real customer.

05

Use it on a live job

Not a test file. A real quote, a real client, a real deadline. That is where the design errors show up.

06

Sharpen or stop

Keep improving it if it earns its keep. If it doesn’t, we say so. You own the code either way.
